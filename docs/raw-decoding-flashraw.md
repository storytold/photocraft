# FlashRaw sensor decoding

Validated on 2026-10-27. PhotoCraft uses `flashraw = 0.1.1` by default for sensor decoding,
with its original decoder for incompatible representations. Both routes use PhotoCraft's
metadata, camera profiles, preview-colour fitting and 16-bit ProPhoto development.
No FlashRaw RGB/ICC/GPU pipeline or memory-mapped input is enabled.

## Native measurement

For the newer 2026-10-28 decode-only matrix (88 files / 20 vendor groups), including all errors,
Builtin discrepancies against LibRaw and codec-specific slowdowns, see the
[full RAW performance report](raw-decode-performance.md). The decode/develop numbers below
are the earlier 2026-10-27 run and use a different timing procedure.

Apple M1 Pro, 16 GiB RAM, release profile. Other task builds were paused while measuring.
Each file is read once, followed by two warmups and seven measured runs; each column is its
own median. Decode includes header parsing, the adapter and PhotoCraft metadata. Development
uses the default AHD method (the generic X-Trans method for RAF). The combined measurement
excludes file I/O, preview-colour fitting and document construction, so it is not total open time.

| Input | Pixels | Builtin decode ms | Auto decode ms | Decode speedup | Builtin combined ms | Auto combined ms |
|---|---:|---:|---:|---:|---:|---:|
| Synthetic uncompressed DNG | 24 MP | 50.692 | 42.484 | 1.19× | 227.892 | 215.648 |
| Synthetic lossless-JPEG tiled DNG | 24 MP | 58.678 | 64.983 | 0.90× | 239.999 | 238.739 |
| Synthetic CR2 | 24 MP | 132.015 | 45.439 | 2.91× | 309.865 | 267.415 |
| Nikon Z6 lossy 12-bit NEF, DSC_0751 | 24 MP | 152.728 | 74.925 | 2.04× | 338.659 | 313.297 |
| Nikon Z6 lossy 14-bit NEF, DSC_0754 | 24 MP | 151.034 | 68.435 | 2.21× | 329.077 | 293.294 |
| Sony RX0 cRAW (Builtin compatibility fallback) | 16 MP | 8.505 | 9.370 | 0.91× | 128.164 | 149.454 |

Independent median development times vary between runs despite identical samples and code.
Treat the decode figures as the evidence for this integration; improvements are codec-specific.
Lossless-JPEG DNG did not improve in this run. No uniform speed multiplier is claimed.
Peak process RSS across each whole six-file run was 1,237,516,288 bytes (Builtin) and
1,186,152,448 bytes (Auto); these are whole-process maxima, not per-file memory requirements.

Reproduce with `cargo run --release -p photocraft-raw --example rawbench -- builtin FILE...`,
then the same command with `auto`. Synthetic 24 MP files are generated by
`rawinfo --write-synthetic DIR`; real files come from `cargo xtask corpus --pixls`.
Use `rawinfo --backend flashraw FILE...` to require the external path without fallback.

## Compatibility and safety

FlashRaw receives borrowed bytes, full uncropped `RawU16`, strict corruption policy, disabled
opcodes and disabled preview fallback. Only unsupported representations fall back. Damage,
allocation failures and exceeded limits stay errors. PhotoCraft checks asymmetric dimensions,
byte/pixel limits, padded tile budgets and lossless-JPEG frame sizes before decoding, and checks
the resulting plane geometry before combining it with its metadata.

Deferred DNG linearization, floating-point/JPEG XL/lossy-JPEG DNG, sub-16-bit Deflate,
Sony cRAW tone curves, NEF sub-16-bit samples stored in 16-bit containers, small vendor sensors,
and other incompatible representations retain the original decoder. DNG crop values are checked
before the external parser: both enormous floats and u32 crop-origin addition have regression
tests. Unsupported sensor data still reaches the existing, explicitly labelled embedded-preview
fallback in I/O. Disabling the default `flashraw` Cargo feature builds the original decoder alone.

Wasm explicitly sets one calling thread; transitive Rayon defaults must not initialize a browser
thread pool. It uses the same Rust adapter and development, with no additional handwritten JS,
worker, SharedArrayBuffer, COOP/COEP or GPU requirement.

## Evidence

- Synthetic regressions cover 8/12/14/16-bit DNG, all eight orientations, lossless JPEG/Deflate,
  metadata and pixel equality, limits, deferred-linearization fallback and hostile crop values.
- All pre-existing pinned camera files keep their exact sensor samples, levels, white balance,
  CFA and crop under Auto. EOS R5 RAW/C-RAW and X-T5 compressed RAF add three CC0 oracles,
  increasing `corpus/pixls` from 11 to 14 files; default and tuned I/O import use full sensor data.
- `rawlook` output for the R5 and X-T5 was inspected against each camera JPEG. PhotoCraft's
  existing preview-colour fit was accepted for both (R5 full-output mean CIE76 delta-E 2.3 after fitting;
  X-T5 4.3). This is estimated rendering, not measured camera calibration.
- Mutation stress on the real R5 RAW, real compressed RAF and synthetic lossless-JPEG DNG:
  250 mutations each, 750 total, zero escaped panics.

See [decoder selection](../crates/raw/README.md#decoder-selection) for the API and fallback details.

## Browser and release package verification

The release site was built and packaged with Trunk 0.22.0, wasm-bindgen 0.2.129 and Binaryen
133. The app wasm is 30,215,910 bytes; its shipped gzip part is 13,188,809 bytes, below the
24 MiB per-file gate. Artifact: `dist/release/photocraft-web-0.16.0.zip`.

The packaged site (the boot loader and compressed wasm part, not only Trunk's direct output)
was served locally and exercised in headless Chrome 156 on the CPU canvas, without cross-origin
isolation or browser worker threads. R5 RAW, R5 C-RAW, compressed X-T5 RAF and Sony RX0 cRAW
compatibility fallback all opened in Camera Raw; Exposure was changed to +0.59 EV and Open
re-developed each original. Screenshots were inspected: R5 RAW/C-RAW remained RGB/16 at
8192 × 5464, RAF at 7728 × 5152, and Sony at 4832 × 3224. No JavaScript runtime errors occurred.
Screenshots are local test artifacts in `/tmp/photocraft-web-{cr3,craw,raf,sony}-opened.png`.

The package test also exposed assumptions in the old packager: Trunk can assign different
content hashes to JS and wasm, and generated JS snippets must accompany the renamed app glue.
The packager now handles both, with `bash packaging/web/package-test.sh` covering matching and
independent hashes, preserved snippets and rejection of ambiguous app glue. CI runs this test.

Validation includes native raw/io tests and raw without default features; clippy for raw/io
with all targets; formatting; layering; the 24-crate wasm gate plus HEIF; `panic_hunt`; the full
corpus gate (5,097 passed, 34 intentionally ignored, using CI's no-LTO/16-codegen release settings);
and `perf --quick --skip-build`. The quick performance run succeeded but skipped comparison
against the stored M4 Pro baseline because the local machine is an M1 Pro. No baseline or
estimated parity percentage was increased.
