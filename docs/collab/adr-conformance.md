# PhotoCraft against ADR-0001…0010 (RFC-0020, mechanism B)

- Дата: 2026-11-25
- Ветка: `collab/adapter` (от `origin/main` 13520900d)
- Отвечает на: `study.md` §11–12, `options.md` §6 — рекомендация B совпала с
  принятым ADR-0001; здесь каждый ADR сверен с кодом PhotoCraft, а не с буквой.
- Механизм B принят (`../.craft/bus/decisions/0001-op-unit.md`): сервер
  исполняет, клиентам уходит авторитетный результат. PhotoCraft добавляет к
  общему конверту только одно: **результат может быть тайловой дельтой**, а не
  командой.

Обозначения: **есть** — модель это уже держит; **адаптер** — решает адаптер без
правок движка; **движок** — нужна точка расширения в upstream; **дыра** —
открытый вопрос, зафиксирован ниже.

## 0001 — единица операции

| требование | PhotoCraft |
|---|---|
| вход `{opId, sessionId, actor, baseVersion, kind, payload, context}` | `Session::execute(id, params)` — единственная точка мутации (`crates/engine-core/src/session/execute.rs:14`), 1 018 команд, `param_schema.rs` + `param_check.rs` дают машиночитаемую схему. Конверт собирает адаптер. |
| `kind ∈ command / primitive / structural` | `command` — одна запись `Session::execute`; `primitive` — нормализованный `paint.stroke` (слой, точки, давление, seed, кисть) или фильтр; `structural` — смена дерева слоёв, маски, смарт-объекта, размера документа. |
| `context` — только явные значения | Обязательно: `paint.*` по умолчанию берёт активный слой, цвет и кисть из сессии; в конверт едут `layer: LayerId`, `target`, полный `points`, `seed`, `brush`. Без этого «та же» команда даёт другой штрих (**адаптер**). |
| сервер исполняет, клиенту авторитетный результат | Пиксели: сервер применяет дельту к своему тайлу и рассылает **результат** (изменённые пиксели), не команду. Структура: сервер исполняет команду, рассылает подтверждённую дельту свойств (**адаптер**). |
| производное не передаётся | `TextLayer::cache`, `ShapeLayer::cache`, `SmartObject::cache`, `FillCache` — вне дельты; каждая реплика пересчитывает из авторитетных полей, commit — на сервере (`options.md` §6). |

**Дыра:** `paint.stroke` помечен `incomplete` в
`crates/engine-paint/src/install.rs:32-54`; allowlist v1 не может включать его
как единственный payload. Дельта тайлов — авторитетна, команда остаётся в
журнале для аудита.

## 0002 — идентификаторы

- `LayerId(u64)` — процессный счётчик с 1 (`crates/doc/src/lib.rs`, `fresh()`);
  в файле PSD — `lyid` (`psd_id`). Для сети нужен **актор-диапазон** или выдача
  сервером; адаптер ведёт карту «серверный ключ ↔ `LayerId`» (**адаптер**).
- Части адресуются `(layer, part)`: `Pixels | Mask`; стиль/коррекция/смарт —
  поля того же слоя (**есть** в модели адаптера).
- Надгробия: удалённый `LayerId` в сессии не переиспользуется; операция по
  удалённому слою — отказ `retryable:false` (**адаптер**).
- Имена — значения, не ключи (`layer.rename` — отдельная операция).

**Дыра:** `LayerId` выдаётся `fresh()` и в одном процессе; два клиента,
создавшие слой одновременно, получат один id. v1 — сервер выдаёт
session-scoped ключ, `LayerId` присваивает сервер при создании слоя.

## 0003 — порядок и версии

- Монотонный `version: u64` на документ — у сервера (**адаптер/сервер**);
  `opId = (clientId, seq)`, окно идемпотентности (**сервер**).
- `baseVersion` — контекст, не блокировка. PhotoCraft: тайловая дельта
  применяется к текущему head; версия тайла отдельно не нужна, пока undo
  проверяет отпечаток (см. 0010).
- Presence не увеличивает версию (**адаптер**).
- Догон: хвост журнала или снапшот `.pcraft` + сброс очереди (**сервер**).

## 0004 — конфликты

- `merge`: правки **разных тайлов** одного слоя параллельны. Правки одного
  тайла — тоже `merge`, если дельта несёт изменённые **пиксели**, а не тайл
  целиком: сервер накладывает их на свой текущий тайл. Это прямое требование
  TASK §5 («пересечение только по реально изменённым пикселям»), и первый
  инкремент адаптера делает именно `TileDelta::Patch`.
- `structural`: дерево слоёв, маска как объект, смарт-объект, размер —
  эксклюзивно, `baseVersion == head`; клиенты не применяют оптимистично.
- Отказы: `{code, retryable, details}`; `retryable:false` для удалённого слоя,
  сдвинутого адреса, защиты слоя (`locks`).
- LWW для пикселей — только «порядок сервера» на уровне пикселя; для структуры
  LWW нет.

## 0005 — снапшоты

- Снапшот сессии — `.pcraft` (родной формат; content-addressed,
  `crates/format/src/store.rs`), метаданные `{version, actor, savedAt, keys,
  fileId}` (**сервер**).
- Pass-through: PSD-блоки, которые модель не разбирает, лежат в
  `Layer::psd_blocks: Vec<([u8;4], Arc<Vec<u8>>)>` и пишутся обратно; `.pcraft`
  моделирует документ целиком. Опасность — производные кэши: снапшот их
  сохраняет, но реплика их не мержит (**есть/адаптер**).
- Журнал обрезается по версии снапшота, 2 снапшота (**сервер**).
- Commit — отдельная операция (0009), падение конвертера не ломает сессию.

## 0006 — presence

- Отдельный тип в том же WS, ≤10 Гц, ≤2 KiB, TTL 30 с, не журналируется.
- PhotoCraft: курсор, выделение/маска, активный слой, вьюпорт pan/zoom, цвет
  метки. Без содержимого. Viewer шлёт presence (**адаптер**).

## 0007 — топология

- Один sync-сервис, per-app адаптер — Rust-крейт, статическая линковка, без
  dylib и `unsafe` (**сервер/адаптер**).
- Room = `(fileId, app)`; сервер — отдельный нативный процесс, не режим
  приложения.

## 0008 — auth

- JWT первым сообщением `hello`, claims `{iss, sub, aud, fileId, app, role,
  sessionId, iat, exp, ver}`; роль проверяется на каждой операции; автор — из
  `sub`, клиентский `author` не принимается (**сервер**).
- Viewer/commenter: presence — да, операция — `forbidden`; в PhotoCraft viewer
  также не двигает вьюпорт другим (это presence, не операция).

## 0009 — commit

- Файл собирает сервер через `Headless::save` (`.pcraft`/PSD/PSB/ORA;
  `crates/engine/.../headless.rs:369-450`), клиент не коммитит.
- Проверка целостности: PSD round-trip сейчас 308/309
  (`docs/file-format-parity.md:26`); предупреждения — списком, не флагом.
- `expectedVersion`/etag → `409` → «Сохранить копию»; предыдущая версия
  сохраняется кабинетом.

**Дыра:** для PSD commit нужен writer из `craft-psd` через `Headless`; сервер
обязан держать тот же `io`-маппинг, что одиночный режим, иначе round-trip
деградирует.

## 0010 — undo и offline

- Per-user стек на актора; шаг — **инверсия затронутых тайлов** (before-образы)
  и, дальше, свойств слоя. `crates/ops` остаётся клиентской историей; серверные
  снапшоты для undo не используются (**адаптер**).
- Undo — новая операция с `baseVersion = head`, проходит роли/lease/конфликты.
- Конфликт undo: тайл изменён другим после шага → частичный отказ
  `{code:"undo-conflict", retryable:false}`, без молчаливой перезаписи. В
  адаптере это отпечаток тайла (FNV-1a по байтам тайла) на момент шага.
- Redo симметрично; лимит 200 шагов / 24 ч на пользователя.
- Offline v1 — только reconnect/догон по `lastVersion`.

## Итог

Все десять ADR ложатся на PhotoCraft без второго движка. Единственное
дополнение к общему конверту — **`TileDelta::Patch`** (разреженные пиксели,
а не тайл целиком): без него пункт TASK §5 «потерь в одном тайле нет» не
выполняется. Три места требуют правок вне адаптера: выдача `LayerId` сервером
(0002), allowlist с неполной схемой `paint.stroke` (0001) и PSD-writer на
сервере (0009).
